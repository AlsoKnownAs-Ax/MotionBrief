# The agent writes a Storyboard, then code per Scene; our code owns everything between Scenes

The agent first writes a Storyboard: structured, validated data that fixes the Scenes, their Scene Types, their content (one shape per Scene Type, with element ids) and the Transcript words each element appears on. It then writes HyperFrames HTML/CSS/GSAP for each lone Scene or Canvas, inside a frame we own (style tokens, safe zones for each Format, motion helpers, reference examples). Our code builds the root composition deterministically from the Storyboard: timing, Transitions, camera moves across a Canvas, Captions and the Voiceover. Opus can already produce good motion graphics; this form is about consistency. The Storyboard keeps structure and pacing checkable. Each piece of Scene code is small enough to lint, check, visually review and regenerate on its own. A Revision can target the Storyboard or a single Scene.

## Considered Options

- **Freeform composition**: the agent writes the whole video as one HyperFrames file. This has the highest quality ceiling, but consistency then rests on prompting alone, errors can land anywhere in one large file, and a Revision can't be scoped.
- **Fixed templates filled with data**: the most consistent option, but the quality ceiling is ours rather than the model's. It needs hand-built 9 Scene Types × 2 Formats × styles, and gives little of the seamless motion the benchmarks set.
- **A "custom" Scene Type as an escape hatch**: rejected. Scene code is already freeform within a Scene Type, and a custom type would bypass the Storyboard contract. Gaps are fixed by adding a Scene Type.

## Consequences

- Timing is written only as word references. Scene code animates against named anchors (`at(id)`) and never writes seconds.
- A validator checks the Storyboard contract. Every Storyboard element must exist in the Scene's DOM under its id and become visible within about 100 ms of its anchor. This runs alongside `hyperframes lint`/`check` and a capped visual review of rendered stills.
- A Scene that still fails after 2 retries is replaced by a plain, word-anchored fallback built from its structured content, and flagged to the user. Generation always finishes with a complete video.
- Scene code is generated by parallel subagents. Consistency comes from the shared frame and tokens, not from one sequential session.
- A Storyboard is specific to one Format. Changing Format is a new generation, not a Revision.
- GSAP is accepted and pinned. Its Standard License prohibits only no-code tools that compete with Webflow's visual animation builder, and it explicitly allows AI-generated code. The motion helpers keep the runtime swappable.
